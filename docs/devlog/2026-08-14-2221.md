## 任务

修复双击 `stringcraft.exe` 后悬浮条窗口“打开后过一会消失”的崩溃问题。

## 本次完成

- 定位根因：Tauri 的 setup 阶段窗口尚未就绪，此时查询窗口句柄/显示器会触发竞态：
  - `position_float_bar` 中调用 `win.current_monitor()` / `win.outer_size()` 返回 `failed to receive message from webview`；
  - `apply_no_activate` 中调用 `win.hwnd()` 返回 `the underlying handle is not available`；
  - Tauri 把 setup 的错误转为 panic，进程随之退出，表现为“窗口显示一会儿就消失”。
- 修复方案：
  - 悬浮条初始定位改为前端页面加载后执行：`currentMonitor()` + `outerSize()` + `setPosition()`，此时窗口已就绪；
  - “不抢焦点（F1.12）”改用窗口配置 `focusable: false`，由 Tauri 在创建窗口时直接设置，不再在 setup 里改 `WS_EX_NOACTIVATE`，并移除对应 FFI 与 `windows` 直接依赖；
  - 新增窗口权限 `allow-current-monitor`、`allow-outer-size`、`allow-set-position`；
  - 悬浮条尺寸由 `PhysicalSize` 改为 `LogicalSize`，修正高 DPI 下的尺寸单位。
- 移除 setup 内用于定位/改窗口样式的代码，setup 只保留：加载配置、安装并注册快捷键、创建托盘。

## 关键决策

- setup 阶段不调用任何依赖窗口/WebView 就绪状态的查询或句柄操作，避免不可靠的时序；这类操作统一放到前端页面加载后。
- 用 `focusable: false` 实现不抢焦点，比运行时改窗口扩展样式更简单可靠，且是 Tauri 2.11 官方支持的配置项。
- 快捷键启动时注册失败只打印日志不阻断启动（如上次崩溃残留实例仍占用快捷键时）。
