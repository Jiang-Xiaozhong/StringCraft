## 任务

修复 M4 引入的“双击 EXE 后窗口崩溃/卡死”问题，恢复 M3 可用的启动与自动替换体验。

## 本次完成

- 新增 panic 钩子：把 panic 信息与调用栈写入 `%TEMP%\stringcraft-panic.log`，无控制台的 GUI 版也能定位崩溃。
- 用 panic 钩子抓到真正崩溃点：WebView2 初始化期间 `WebResourceRequestedEventHandler` 回调内 panic，跨 FFI 无法 unwind，触发 `0xc0000409` 快速失败（崩溃）；卡死同样源于 WebView2 初始化未完成。
- 定位根因：
  - 窗口配置 `focusable: false` 与当前 Tauri/WebView2 初始化不兼容，是崩溃/卡死主因；
  - setup 阶段调用 `current_monitor()` / `outer_size()` / `hwnd()` 本就在窗口就绪前，不可靠。
- 修复：
  1. 移除 `focusable: false`，保留 `focus: false`；
  2. setup 只保留配置加载、快捷键安装/注册、托盘创建，不再做任何窗口句柄/显示器查询；
  3. 悬浮条初始定位放回前端页面加载后执行；
  4. “不抢焦点（F1.12）”改为前端加载后调用 `apply_no_activate` 命令，在窗口就绪后设置 `WS_EX_NOACTIVATE`。

## 关键决策

- 不在 setup 阶段做任何依赖窗口/WebView 就绪状态的查询或句柄操作。
- 不使用 `focusable: false` 这一配置项（当前版本下与 WebView2 初始化冲突），改回运行时设置 `WS_EX_NOACTIVATE`，并延后到窗口就绪后执行。
- 保留 panic 钩子作为长期诊断手段：GUI 版崩溃时可直接查看日志文件，无需控制台。
